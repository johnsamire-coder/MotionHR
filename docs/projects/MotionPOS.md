## 1. نظرة عامة

Motion POS برنامج كامل لإدارة الكافيه، بيشتغل من أي متصفح (كمبيوتر، تابلت، موبايل)، ومعاه لابتوب في المحل بيكمّل الشغل لو النت قطع.

| القسم | فيه إيه |
| --- | --- |
| البيع | الكاشير، والطاولات، والويتر، وشاشة التحضير (مطبخ/بار/شيشة)، ومنيو QR للزبون |
| الفلوس | الورديات، والخزينة، والمصروفات، والعهد، والإكراميات، والضيافة، والقيود المحاسبية |
| المخزن | المشتريات، والاستلام، والجرد الأعمى، والهالك، والتحويل بين المخازن، والوصفات اللي بتخصم مع البيع |
| الإدارة | التقارير، ولوحة المتابعة، والموظفين، والحضور، والمرتبات، والعملاء، والشكاوى |

| الحاجة | الرقم |
| --- | --- |
| ملفات الشاشات | `index.html` + 23 ملف JavaScript في `js/` (حوالي 8600 سطر) |
| جداول القاعدة | حوالي 90 جدول |
| دوال السيرفر الآمنة (`*_secure` و `*_public`) | 128 دالة |
| ملفات تعديل القاعدة | 34 ملف (من `001` لـ `034`) |
| التقارير | 46 تقرير في 10 مجموعات |

## 2. طريقة البناء (التقنيات)

| الطبقة | التقنية |
| --- | --- |
| الشاشات | HTML عادي + Tailwind + JavaScript عادي (من غير React ولا بناء). المكتبات محفوظة جوه `vendor/`: `tailwind.js`، `supabase.js`، `chart.umd.js` (رسوم)، `exceljs.min.js` (تصدير Excel)، `qrcode.min.js`، والخطوط |
| القاعدة | PostgreSQL 17. كانت على Supabase، وبقت على سيرفر الشركة |
| الـ API | **PostgREST** (بيحوّل دوال القاعدة لروابط API). على السيرفر اسمه الخدمة `motionpos-api` على `127.0.0.1:3010` |
| مكتبة الاتصال | `supabase-js`، وبتكلّم PostgREST بنفس الطريقة (`/rest/v1/rpc/...`) |
| الويب سيرفر | nginx على السيرفر (بشهادة SSL). على لابتوب المحل Caddy على بورت 8080 |
| النشر القديم | Vercel (الفرع `main` = الموقع الحقيقي، `dev` = التجربة). الموقع القديم `motion-pos.vercel.app` بيحوّل لوحده على `pos.jssolutions-eg.com` |

**الفكرة:** مفيش كود سيرفر منفصل (لا Django ولا Node). كل المنطق (الأسعار، والإجماليات، وخصم المخزن، والقيود) مكتوب كدوال جوه PostgreSQL، والشاشة بتنادي الدالة بالاسم.

## 5. المبدأ الأساسي للأمان

> **"السيرفر هو الحَكَم، والمتصفح بيعرض بس."**

- كل حساب فلوس أو كميات بيحصل جوه دالة في القاعدة. الشاشة بتبعت "عايز إيه" (الصنف والكمية)، مش "بكام".
- كل الجداول مقفولة (RLS من غير قواعد). الكتابة والقراية من خلال الدوال بس.
- كل حركة مخزن بتعدّي من `record_stock_movement`، وهي اللي بتحدّث الرصيد ومتوسط التكلفة.
- كل حركة فلوس بتعمل قيد تلقائي.
- مفيش مسح نهائي لأي حاجة مالية: إلغاء أو عكس بس، بسبب مكتوب وموافقة، ومتسجّل مين عمل إيه وإمتى.
- الأرقام السرية متشفّرة (bcrypt عن طريق `pgcrypto`)، والتحقق منها جوه السيرفر بس.
- **تذكرة الوردية:** الدخول بيرجّع `session_token` (64 حرف) صالح 12 ساعة، والقاعدة بتحفظ بصمته بس. أي دالة حساسة أول سطر فيها `require_session(p_token)`.
- حد للمحاولات: 10 غلطات من نفس الجهاز أو 100 من الكل في 10 دقايق ← قفل 10 دقايق (للدخول ولرقم المدير).
- الدالة اللي بتتأكد من رقم سري مابتطلّعش خطأ لو الرقم غلط، بترد `{ok:false}`، علشان تسجيل المحاولة مايتلغيش.
- ممنوع أي سر يدخل المستودع. النسخ الاحتياطي برّه المشروع.

## 6. الدخول والأدوار والصلاحيات

### شاشة الدخول (`#login-screen`)
- لوحة أرقام (0–9)، وزرار **مسح**، وزرار **دخول**.
- `loginWithPin()` ← دالة `staff_login(p_pin)` ← بترجع `{ok, staff, role, branch, tax, session_token}` أو `{ok:false, reason:'wrong_pin'|'locked'}`.
- الخروج: زرار **خروج 🚪** ← `staff_logout`.
- بعد الدخول بيتحمّل: إعدادات البرنامج (`app_settings_get_secure`)، وصلاحيات الدور (`pos_settings_list_secure`)، وبيرجع لآخر تبويب كان مفتوح.

### الأدوار الأساسية
| الدور | بيعمل إيه |
| --- | --- |
| `owner` المالك | كل حاجة. بيعتمد أوامر الشراء الكبيرة، وبيغيّر يوم الشغل وحد مشتريات المدير، وزرار التصفير ليه هو بس. تبويب الصلاحيات وإعدادات الشغل ليه هو بس |
| `branch_manager` مدير الفرع | كل شاشات الفرع. أمر الشراء بتاعه بيتعتمد لوحده لو مجموع اليوم تحت حد المدير (200 جنيه)، ويوافق على الضيافة لحد 500 جنيه في اليوم |
| `cashier` الكاشير | الكاشير وورديته، والحضور |
| `waiter` الويتر | الطاولات والطلبات وتأكيد الـ QR. اسمه بيتحط لوحده على الطلب |
| `storekeeper` أمين المخزن | أمر الشراء، والاستلام، والموردين، والهالك، والتحويل، والجرد |

المالك يقدر يضيف أدوار جديدة من **الموظفين ← الصلاحيات**.

### الصلاحيات التفصيلية (`canDo()` في الشاشة + جدول `role_permissions`)
`po_create` إنشاء أمر شراء · `po_approve` اعتماد · `po_receive` استلام · `po_post` ترحيل للمخزن · `po_invoice` فاتورة مورد · `supplier_pay` سداد مورد · `suppliers_manage` إدارة الموردين · `inv_waste` هالك · `inv_transfer` تحويل · `inv_stocktake` جرد · `treasury_transfer` تحويل بين الخزن · `day_close` تقفيل اليوم · `tips_distribute` توزيع الإكراميات · `exp_record` تسجيل مصروف · `exp_recurring` المتكررة · `exp_categories` البنود · `exp_custody` العهد · `staff_manage` إدارة الموظفين · `payroll_approve` اعتماد المرتبات · `payroll_pay` صرف المرتبات · `acc_manual` قيد يدوي · `settings_menu` تعديل المنيو · `hospitality` الضيافة.

### رقم المدير
- نافذة **منطقة محمية** (`#pin-auth-modal`): خانة الرقم + **تأكيد** + **إلغاء**. بتنادي `verify_manager_pin` على السيرفر.
- بيتطلب في: إلغاء صنف اتبعت للمطبخ، والخصم اليدوي، وإلغاء الطلب، والضيافة، وفتح الشاشات المحمية.

كل تبويب بيظهر حسب صلاحية الدور.

### 7.1 لوحة التحكم (`dashboard`)
- **الفترة:** اليوم · الأمس · آخر 7 أيام · هذا الشهر · الشهر الماضي · فترة مخصصة.
- فلتر الفرع، وتبويبين: **نظرة عامة** و **الأرباح والخسائر اليومية**.
- مربعات أرقام بالمقارنة بالفترة اللي قبلها، ورسوم أعمدة ودوائر (Chart.js).
- الدوال: `dashboard_secure`، `pnl_daily_secure`. اليوم محسوب بـ"يوم الشغل" (من 8 الصبح لـ 8 الصبح).

### 7.2 الكاشير (`pos`)
**فوق:** نوع الطلب: **صالة** · **تيك أواي** · **توصيل** · **استلام** (اللي يظهر منهم حسب الإعدادات).

**الجزء الأول، خريطة الصالة والطاولات:** اختيار المنطقة، والطاولات بألوان (فاضية/مشغولة). الضغط على طاولة يفتح طلبها.

**الجزء التاني، منيو الأصناف:** أزرار الأقسام (`category-pills`)، وخانة بحث، وكروت الأصناف بالصور. الصنف اللي ليه إضافات بيفتح نافذة الإضافات (اختيار إلزامي/اختياري حسب القاعدة).

**الجزء التالت، التذكرة (الفاتورة):**
- رقم الطلب، وحالته، والطاولة، والنوع.
- الويتر (`select-waiter`)، وعدد الضيوف، والعميل: تليفون + **بحث** + **✖** (إزالة)، ولو مش موجود بيتضاف بسرعة.
- الأصناف: كمية، وملاحظة (ملاحظات جاهزة زي "بدون بصل")، وإلغاء صنف (بسبب، ورقم المدير لو اتبعت).
- الإجماليات: الإجمالي الفرعي، **الضريبة (14% VAT) ⚙️** (زرار تشغيل/إيقاف)، **الخدمة (12%) ⚙️**، الخصم، الإجمالي.

**زراير التذكرة:**
| الزرار | بيعمل إيه | دالة السيرفر |
| --- | --- | --- |
| خصم 🏷️ | يختار خصم من القايمة أو خصم يدوي بمبلغ (بموافقة المدير) | `apply_order_discount_secure` |

| إرسال للمطبخ 👨‍🍳 | يبعت الأصناف الجديدة لشاشة التحضير (وورقة مطبخ لو مفيش شاشة) | `submit_order_items_secure` |
| الحساب 🧾 | يطبع الحساب قبل الدفع | `order_print_data_secure` |
| دفع وإغلاق 💳 | نافذة الدفع | `close_order_secure` |

**نافذة الدفع (`#payments-modal`):** الإجمالي المطلوب، والمحصّل، والباقي. طرق الدفع: **نقدي** · **بطاقة** · **إنستاباي** · **محفظة** · **على الحساب (آجل)**. زرار **إضافة طريقة سداد أخرى ➕**، وخانة **الإكرامية (Tips)**، وزرار **ضيافة 🎁**، وزرار **تأكيد الإغلاق 💳**.
- الدفع كله عملية واحدة على السيرفر: بيتأكد إن المدفوع = المطلوب، ويسجل الدفعات، ويفصل الإكرامية، ويخصم الخامات بالوصفة، ويعمل قيد المبيعات وقيد التكلفة، ويقفل الطلب.
- بعد الدفع ممكن يظهر زرار "ابعت رسالة شكر" على واتساب لو العميل ليه رقم.

**الضيافة 🎁:** فئة الضيافة: ضيف المالك · أهل · موظفين · دعاية. بتتقيد بالتكلفة مش بالسعر، وبتطبع ورقة ضيافة. (`hospitality_close_secure`)

**إلغاء الطلب على الموظف:** لو اتختار موظف، الطلب بيتحسب هالك، وتكلفة الخامات بس بتتخصم منه (مدين 1130 ذمم الموظفين، دائن 5100)، وبتتخصم من مرتبه.

> زرار "مرتجع طلب مدفوع" **اتشال** من الشاشة، والدالة `refund_order_secure` لسه موجودة.

البيانات بتتحدّث لوحدها كل شوية (`posStartAutoRefresh`).

### 7.3 المطبخ / شاشة التحضير (`kds`)
- تبويبات الأماكن: **مطبخ** · **بار** · **شيشة** (حسب الإعدادات).
- كروت الطلبات فيها الأصناف والإضافات والملاحظات وعدّاد الوقت. اللون بيتغيّر لما الطلب يتأخر (الحد بالدقايق من الإعدادات).
- مؤشر 🔥 **الزحمة**: لو عدد الطلبات المفتوحة عدّى حد معيّن، وقت التحضير بيزيد.
- زرار **تحديث 🔄**، وصوت تنبيه للطلب الجديد، وتحديث تلقائي (Realtime أو كل كام ثانية).
- تغيير حالة الطلب ← `kds_station_set_secure`.

### 7.4 الوردية (`shift`)
- **فتح وردية** بعهدة أول المدة (الفكة الافتراضية من الإعدادات) ← `shift_open_secure`. **وردية واحدة بس مفتوحة في الفرع**.
- **توريد (Drop)** و **إيداع في الدرج** أثناء الوردية ← `shift_cash_move_secure`.
- **قفل الوردية:** الكاشير بيعدّ الفلوس **من غير ما يشوف المفروض**، والسيستم يطلّع العجز أو الزيادة ← `shift_close_secure`.
- تقرير الوردية بكل طرق الدفع، وطباعته (`printShiftStatement`).
- **بصمة الحضور والانصراف:** كل موظف بيكتب رقمه السري من حسابه هو ← `attendance_punch_secure` (رقم موظف تاني بيترفض: "الرقم السري ده مش بتاعك").

**قواعد كتابة ملف قاعدة جديد:**
1. `begin` و `commit`، وفحص الترميز (`length('إكراميات') <> 8` يوقف الملف).
2. حارس الإصدار: يقبل الإصدار اللي قبله أو نفسه بس.
3. الدالة المتعدّلة تتنسخ من آخر ملف معرّفها بالظبط، والتعديل بس هو اللي يتغيّر.
4. رفع الإصدار في `motionpos_version_public`، وحلقة الصلاحيات (grants).
5. اختبار داخلي بيتراجع وبيطبع `MOTIONPOS-0XX-SELFTEST-OK`.
6. `notify pgrst, 'reload schema'` قبل `commit`.
7. ملف اتطبق مايتعدّلش أبداً. أي تغيير = ملف جديد.
8. بصمة الملف تتضاف في `$Files` جوه `tools/motionlocal.ps1`، و`$LastVersion` يتغيّر (البصمة = أول 16 حرف من sha256 بعد شيل `\r`).

## 13. الشغل من غير نت (لابتوب المحل والمزامنة)

- اللابتوب عليه نسخة كاملة: PostgreSQL 17 (بورت 54329) + PostgREST (54330) + Caddy للشاشات (8080).
- **المزامنة** بين اللابتوب والسيرفر كل 30 ثانية تقريباً، من خلال `sync_log` ومستخدم `motionpos_sync` (اتصال مشفّر بباسورد).
- لو النت قطع، الشاشات بتشتغل عادي على اللابتوب، ولما يرجع البيانات بتتزامن.
- تاسك ويندوز اسمها **"MotionPOS Shop Server"** بتشغّل كل حاجة لوحدها مع تشغيل الجهاز (`-Step autostart`).
- `warehouse_stock` مش بيتزامن؛ كل جهاز بيحسبه من `stock_movements`. علشان كده `-Step compare` بيبيّن فرق شكلي فيه.
- `motionpos.sync_apply='on'` بيوقّف تسجيل المزامنة (وهي بتطبّق)، و`motionpos.system_reset='on'` بيعدّي أقفال المسح.
- **ويندوز عربي:** لازم `LC_MESSAGES=C` وإلا PostgREST بيقع (مشكلة libintl).
- عنوان المزامنة محفوظ متشفّر بيوزر الويندوز في `D:\MotionLocal\secret\cloud_conn.dat`.

## 14. التنصيب والتشغيل

### على السيرفر (مرة واحدة)
```bash
sudo bash /opt/motionpos/repo/tools/motionpos_server.sh install
```
الأداة بتعمل:
1. تتأكد إن الدومين `pos.jssolutions-eg.com` بيشاور على السيرفر (سجل A في Namecheap).
2. تنصّب PostgreSQL 17 ككلستر منفصل `motionpos` على بورت 5433 (من غير ما تلمس قاعدة MotionHR).
3. تعمل الأدوار (`anon`, `authenticated`, `authenticator`, `service_role`, `motionpos_sync`) وتحفظ الباسوردات في `/etc/motionpos`.
4. تحمّل القاعدة من `schema_2026-10-06.sql` وكل الملفات من 001.
5. تنزّل PostgREST وتعمله خدمة `motionpos-api` على `127.0.0.1:3010`.
6. تنسخ الشاشات لـ `/var/www/motionpos`، وتعمل موقع nginx بشهادة SSL، و`/rest/v1` بيوصّل للـ API.
7. تعمل النسخ الاحتياطي اليومي.

> لو اتشغّلت تاني بعد ما خلصت بترفض (علشان البيانات ماتضيعش). المسموح بعدها `update`.

### على لابتوب المحل (مرة واحدة)
```powershell
powershell -ExecutionPolicy Bypass -File D:\MotionLocal\tools\motionlocal.ps1 -Step setup
powershell -ExecutionPolicy Bypass -File D:\MotionLocal\tools\motionlocal.ps1 -Step cloud
powershell -ExecutionPolicy Bypass -File D:\MotionLocal\tools\motionlocal.ps1 -Step autostart
```
- `setup` بينزّل PostgreSQL وPostgREST وCaddy، ويعمل القاعدة المحلية.
- `cloud` بيربط اللابتوب بالسيرفر للمزامنة.
- `autostart` بيعمل التاسك.

### عميل جديد
`-Step newclient` بيضيف سطر موقع العميل في `MOTION_SITES` جوه `js/config.js`.

### التطوير
مفيش بناء. افتح الملفات وعدّل، وجرّب على أي سيرفر ملفات بسيط. اختبار الشاشات:

## 15. طريقة التحديث والنشر

### تعديل في الشاشات بس
1. التعديل والتجربة والرفع على GitHub (`dev` و `main`).
2. **شاشة السيرفر:**
   ```bash
   sudo bash /opt/motionpos/repo/tools/motionpos_server.sh update && sudo git -c safe.directory='*' -C /opt/motionpos/repo log -1 --format=%h
   ```
3. **شاشة اللابتوب:**
   ```powershell
   if ($env:USERNAME -ne 'MotionDev') { 'الجهاز ده مش لابتوب المحل ❌' } else {
   $shop = 'D:\SmartPOS'; $tool = 'D:\MotionLocal\tools\motionlocal.ps1'
   git -C $shop fetch -q origin; git -C $shop merge --ff-only origin/dev
   "نسخة المحل: " + (git -C $shop rev-parse --short HEAD)
   powershell -ExecutionPolicy Bypass -File $tool -Step update }
   ```
4. **Ctrl + F5** على كل الأجهزة.

### ملف قاعدة جديد (0XX)
1. **السيرفر:** `update` ← `pg_dump` نسخة احتياطي ← `motionpos_server.sh sql /opt/motionpos/repo/supabase/migrations/0XX_....sql` (الملف يتطبق كله أو مايتطبقش خالص).
2. **اللابتوب بعد السيرفر:** `pause` ← `git merge` ← `psql -f` للملف ← التأكد من الإصدار ← نسخ الأداة لـ `D:\MotionLocal\tools` (بعد نسخة `.bak`) ← `update` ← `resume` ← إعادة تشغيل التاسك ← `status`.

> المزامنة مابترجعش إلا بعد ما الملف يتطبق على الجهازين. وأداة اللابتوب مابتتنسخش مع `update`، لازم تتنسخ بالإيد.

### تغيير بيانات بس (من غير ملف قاعدة)
على السيرفر بس، والمزامنة بتوصّله للابتوب. لازم UUID ثابتة (uuid5) لأي حاجة جديدة، وحارس يمنع التكرار، ونسخة احتياطي قبلها.

### قواعد الشغل
- الشغل على `dev`، وبعد التأكد يتنقل لـ `main` (`git merge --ff-only dev`).
- لصقات السيرفر اللي فيها عربي بتتبعت base64 جوه heredoc وبتتأكد بـ sha256.
- أي أمر بيطلب باسورد يبقى آخر سطر في اللصقة لوحده.
- ملفات الإعدادات تتكتب من غير BOM.
